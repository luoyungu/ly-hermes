# 落云.Hermes 改动说明（2026-05-23 ~ 2026-05-24）

> 本文档记录本轮较大改动的**内容、架构、使用方式**，以及每项改动的**改进意义**——说明「为什么要做」，而不只是「做了什么」。

---

## 一、总览：这轮改动的核心目标

### 1.1 背景问题

在改动之前，Hermes 只有「本机 Electron 桌面客户端」这一种形态：

- 所有能力通过 **IPC** 与主进程通信
- 用户通过 **本地密码** 登录
- 内置 HTTP 服务（8787 端口）主要用于 **员工嵌入页（embed）**，`/app` 路径要么不存在，要么体验与桌面严重不一致

随着使用场景扩展，出现了三类真实需求：

| 需求场景 | 改动前的问题 |
|---------|-------------|
| 在浏览器打开 `/app`，像桌面一样用 | 被要求输入 API Token，与桌面密码体系割裂；大量功能是空壳 stub |
| 另一台电脑只装轻量客户端，远程管理主机 | 没有「纯客户端模式」，必须在本机跑完整 Agent |
| 手机/平板/局域网内其他设备访问 | Web 服务默认只监听 `127.0.0.1`，外部无法访问 |

### 1.2 改动后的目标形态

```
┌─────────────────────────────────────────────────────────────┐
│                    Hermes 主机（local 模式）                  │
│  ┌──────────────┐   IPC    ┌──────────────┐                 │
│  │ Electron 桌面 │ ◄──────► │  Main 进程   │                 │
│  └──────────────┘          │  + SQLite    │                 │
│  ┌──────────────┐  Session  │  + Agent     │                 │
│  │ 浏览器 /app   │ ◄──────► │  + HTTP 8787 │                 │
│  └──────────────┘  Cookie   └──────┬───────┘                 │
└────────────────────────────────────│─────────────────────────┘
                                     │ Bearer Token (/api/v1)
                    ┌────────────────▼────────────────┐
                    │  远程 Hermes 客户端（client_only） │
                    │  或第三方程序化调用               │
                    └─────────────────────────────────┘
```

**改进意义（总述）：**

1. **统一体验**：本机 Web 端（`/app`）与桌面客户端使用同一密码、同一用户库、同一套功能，不再出现「Web 是阉割版远程客户端」的割裂感。
2. **灵活部署**：支持「重节点 + 轻客户端」架构，一台机器跑 Agent，多台设备只做管理入口。
3. **多入口共存**：桌面 IPC、Web Session、Remote API Token 三条通道各司其职，而不是强行混用一套鉴权。

## 二、双模式部署架构（local / client_only）

### 2.1 改动内容

新增部署模式，存储在 SQLite `settings` 表（`app.deployment_mode`）：

| 模式 | 含义 |
|------|------|
| `local` | 本机完整模式：安装 Agent、管理员工、本地推理，**默认模式** |
| `client_only` | 纯客户端模式：不安装 Agent，所有员工/聊天/设置操作转发到远程节点 |

**核心文件：**

- `src/main/deployment.ts` — 模式读写、远程连接配置、API Token 生成、监听地址策略
- `src/main/ipc/remote-handle.ts` — `ipcHandle()` 包装器：`client_only` 时自动走远程 HTTP，`local` 时走本地逻辑
- `src/core/remote/remote-backend.ts` — 远程 API 客户端封装
- `src/core/remote/remote-client.ts` — 底层 HTTP/SSE 通信

**初始化向导（Onboarding）** 第一步新增「选择使用方式」：

- 选 **本机模式** → 安装 Agent → 配置 API Key → 设置密码
- 选 **纯客户端** → 填写远程节点地址 + API Token → 设置密码

### 2.2 改进意义

| 意义 | 说明 |
|------|------|
| **降低多设备使用成本** | 家里/公司一台性能机器跑 Agent，笔记本、平板只装 100MB 级客户端，不必每台都配 Python 环境 |
| **职责分离更清晰** | 「算力节点」和「操作入口」解耦，符合实际运维场景 |
| **向后兼容** | 已有用户默认 `local`，不影响现有单机使用习惯；新用户可按需选择 |

## 三、Remote API（`/api/v1/*`）

### 3.1 改动内容

在内置 HTTP 服务上新增 REST API 层，供远程客户端和程序化调用：

**路由结构（`src/server/routes/v1/`）：**

| 模块 | 路径前缀 | 能力 |
|------|---------|------|
| 员工 | `/api/v1/employees` | CRUD、唤醒/休眠/重启、Soul/Config/Env/Tools/Memory/Skills |
| 聊天 | `/api/v1/chat` | 流式对话、中止、审批 |
| 会话 | `/api/v1/sessions` | 列表、消息、搜索、删除 |
| 技能 | `/api/v1/skills` | 安装/卸载/配置 |
| 事件 | `/api/v1/events` | SSE 推送（员工状态、会话更新、Cron 等） |
| 节点 | `/api/v1/node/info` | 节点信息 |

**鉴权方式（`src/server/middleware/auth.ts`）：**

```
请求 /api/v1/*
    │
    ├─ 有效 Web Session Cookie？ ──► 放行（本机/局域网 Web 登录用户）
    │
    └─ Bearer Token == api_token 且「允许远程连接」已开启？ ──► 放行（远程客户端）
    │
    └─ 否则 ──► 401 / 403
```

**监听地址策略（`getRemoteServerListenConfig()`）：**

| 「允许远程连接」 | 监听地址 | 谁能访问 |
|-----------------|---------|---------|
| 关闭 | `127.0.0.1` | 仅本机 |
| 开启 | `0.0.0.0`（默认） | 本机 + 局域网/外网（取决于防火墙） |

### 3.2 改进意义

| 意义 | 说明 |
|------|------|
| **标准化远程接口** | 远程客户端不再依赖 Electron IPC 黑科技，改用 HTTP REST + SSE，可调试、可扩展、可被第三方集成 |
| **Web Session 与 Token 并存** | 本机用户用密码登录得 Session，远程设备用 Token，两种身份体系互不干扰 |
| **安全分级** | 默认只绑 `127.0.0.1`，避免用户无意中把服务暴露到公网；需要局域网访问时显式开启「允许远程连接」 |

## 四、Web 全功能客户端（`/app`）

### 4.1 改动内容

新增独立 Web 应用构建产物：

- 构建配置：`vite.web.config.ts`
- 构建命令：`npm run web:app:build` → 输出到 `dist-web/app/`
- 入口：`src/web/app/WebApp.tsx`
- HTTP 静态服务：`/app` 路径（`src/server/index.ts` → `handleAppStatic`）

**Web 端复用桌面 UI 组件**（通过 Vite alias `@renderer`），聊天、员工管理、日程、设置、关于等页面与桌面共用同一套 React 代码。

**API 适配层：** `src/shared/hermes-api/web-hermes-api.ts`

- 桌面端：`window.hermesAPI` 走 Electron preload → IPC
- Web 端：注入 `createWebHermesAPI()` 实现的同名 API，底层走 HTTP

### 4.2 鉴权改造（本轮最关键的用户体验修复）

#### 改动前（错误设计）

```
浏览器访问 /app
    → 要求输入 API Token
    → authLogin 是空 stub（直接返回 success）
    → getDeploymentMode 固定返回 client_only
    → 设置/安装/模型等大量接口返回空数据
```

#### 改动后（正确设计）

```
浏览器访问 /app
    → 与桌面相同的密码登录页
    → POST /api/auth/login → 验证 desktopAuthService（SQLite 用户库）
    → 成功则 Set-Cookie: hermes_session（HttpOnly, SameSite=Lax, 7天）
    → 后续请求 credentials: 'include' 自动带 Cookie
    → /api/v1/* 和 /api/local/invoke 均可用
```

**新增 HTTP 端点：**

| 端点 | 方法 | 作用 |
|------|------|------|
| `/api/auth/login` | POST | 密码登录，写 Session Cookie |
| `/api/auth/logout` | POST | 登出，清 Cookie |
| `/api/auth/me` | GET | 获取当前登录用户 |
| `/api/auth/check-initialized` | GET | 是否已完成初始设置 |
| `/api/auth/setup-password` | POST | 首次设置密码 |
| `/api/auth/change-password` | POST | 修改密码 |
| `/api/auth/mode` | GET | 获取部署模式 |
| `/api/auth/app-version` | GET | 应用版本号 |
| `/api/local/invoke` | POST | Web 端调用本地 IPC 能力的桥接 |

**用户库统一：** HTTP 服务不再使用独立的 `~/.lyhermes-server/users.json`，改为 `desktopAuthService`（SQLite），与桌面客户端完全一致。

### 4.3 Web API 桥接（`/api/local/invoke`）

**问题：** 桌面有大量 IPC 通道（设置、模型、安装、主题、宠物等），Remote API（`/api/v1`）只覆盖了员工/聊天/会话，Web 端如果只有 v1 会导致设置页等功能不可用。

**方案：**

1. `src/main/ipc/web-api-ipc.ts` — `webIpc()` 包装器：注册 IPC 的同时登记到 Web API 注册表
2. `src/server/web-api-registry.ts` — 通道名 → 处理函数的 Map
3. `POST /api/local/invoke` — 携带 `{ channel, args }`，Session 鉴权后调用对应处理函数

已桥接的模块包括：`config.ts`（全部 IPC）、`auth-ipc.ts`、`server-manager.ts`（部署/远程/Web 服务）、`pets.ts`、`sessions.ts`（备份/导入）、`index.ts`（安装/日志/版本）等。

### 4.4 改进意义

| 意义 | 说明 |
|------|------|
| **「浏览器 = 桌面」** | 用户心智模型统一：打开 `/app` 就是打开 Hermes，不是打开一个需要特殊 Token 的「远程管理面板」 |
| **密码优于 Token（本机场景）** | 密码是用户主动设置的、可记忆的；Token 是系统生成的、用于机器间通信的——在本机 Web 场景强行要 Token 是反直觉的 |
| **功能不再阉割** | 通过 invoke 桥接，Web 端设置、模型、安装状态等与桌面一致，避免「同一个产品两个残缺版本」 |
| **Session 比 Token 更安全（Web 场景）** | HttpOnly Cookie 不被 JS 读取，SameSite 防 CSRF；Token 写在 sessionStorage 里反而更容易被 XSS 窃取 |
| **复用 UI 代码** | Web 与桌面共用 React 组件，后续功能只需维护一份界面逻辑 |

## 五、远程客户端（client_only 模式）

### 5.1 改动内容

**IPC 代理：** `src/main/ipc/remote-handle.ts`

```typescript
ipcHandle("employee:list", localHandler)
// client_only 时 → remoteBackend.listEmployees() → HTTP /api/v1/employees
// local 时       → localHandler() → 本地 employees.ts
```

**远程事件桥接：** `src/main/ipc/remote-events.ts`

- 订阅远程节点 `/api/v1/events` SSE
- 转发 `employee-status-changed`、`session-updated`、`cron-session-created` 等到本地渲染进程
- 健康检查轮询 + 断线重连

**UI 组件：**

- `RemoteConnectionProvider.tsx` — 全局远程连接状态
- `ConnectionStatus.tsx` — 顶栏连接状态指示器
- `useDeploymentMode.ts` / `useRemoteConnectionStatus.ts` — 响应式 Hook

**Settings 页面：**

- `local` 模式：显示「内置 Web 服务」「允许远程连接」开关 + API Token
- `client_only` 模式：显示远程节点配置（地址/端口/Token）+ 切换回本机模式

### 5.2 改进意义

| 意义 | 说明 |
|------|------|
| **真正的轻量客户端** | 不在客户端机器上安装 Python/Agent，减少环境依赖和磁盘占用 |
| **实时状态同步** | SSE 事件桥接让远程客户端也能看到员工上线/下线、Cron 执行结果，而不是每次手动刷新 |
| **模式可随时切换** | Settings 里可切回 local 模式，适应「先在远程用着，后来想在本机也跑 Agent」的场景 |

### 6.1 初始化向导（Onboarding）

| 改动 | 改进意义 |
|------|---------|
| 新增「选择使用方式」步骤（本机 / 纯客户端） | 首次启动即明确部署形态，避免用户不知道产品支持两种用法 |

| 改动 | 改进意义 |
|------|---------|
| `WindowControls` 仅在 Electron 环境渲染 | 修复 Windows 浏览器访问 `/app` 时出现无效的最小化/最大化/关闭按钮 |

| Web 小屏保留汉堡菜单 | 移动端 Web 仍可打开侧边导航 |

| 改动 | 改进意义 |
|------|---------|
| `ThemeProvider` 默认 `light`；`:root` CSS 变量绑浅色 | 新用户首次打开不再默认暗色，与 Onboarding 浅色风格一致 |

### 6.4 Layout 顶栏逻辑

| 改动 | 改进意义 |
|------|---------|
| 连接状态栏仅在 `client_only` 模式显示 | local 模式（含 Web 本机访问）不需要显示「远程连接状态」，减少干扰 |

### 8.1 新增/重构的模块

| 路径 | 作用 |
|------|------|
| `src/main/services/employee-api.ts` | 员工 CRUD 逻辑从 `employees.ts` 抽出，供 IPC 和 HTTP v1 共用 |

### 8.2 改进意义

| 意义 | 说明 |
|------|------|

## 十、使用指南

### 10.1 本机浏览器访问（推荐）

1. 打开 Hermes 桌面版（**local 模式**）
2. **设置 → 基础设置 → 开启「内置 Web 服务」**
3. 浏览器访问 `http://127.0.0.1:8787/app`
4. 输入与桌面**相同的密码**登录

> 不需要开启「允许远程连接」，不需要 API Token。

### 10.2 局域网其他设备浏览器访问

1. 主机：**同时开启**「内置 Web 服务」+ **「允许远程连接」**
2. 查主机局域网 IP（如 `192.168.1.100`）
3. 其他设备浏览器访问 `http://192.168.1.100:8787/app`
4. 输入密码登录
5. 确保 Windows 防火墙放行 8787 端口

### 10.3 另一台电脑装轻量客户端

1. 安装 Hermes，初始化时选 **「纯客户端模式」**
2. 填远程节点 IP、端口、API Token（从主机 Settings → 允许远程连接 处复制）
3. 正常使用，功能与主机桌面版一致（不含本机 Agent 安装）

### 10.4 开发调试

```bash
unset ELECTRON_RUN_AS_NODE && npm run dev
# 桌面版启动后，开启 Web 服务，访问 http://127.0.0.1:8787/app
```

## 十一、已知限制与后续可改进项

| 限制 | 说明 | 影响 |
|------|------|------|
| Web Session 存内存 | 重启 Hermes 后 Web 需重新登录 | 低：桌面端同理 |
| Web 端安装进度 | `start-install` 的进度推送依赖 Electron `webContents.send`，Web 端暂不支持实时进度条 | 中：可通过 SSE 扩展 |
| Web 端文件操作 | `getPathForFile`、`saveWallpaperFile`、应用更新等 Electron 专属能力不可用 | 低：浏览器天然限制 |
| 安装包不含 Python | 本机模式 Agent 安装依赖系统 Python 3.11+ | 中：后续可内置 runtime |
| API Token 无过期机制 | Token 长期有效，需手动轮换 | 低：内网场景可接受 |
| `employee:create` 与 `employee-api` 有重复逻辑 | 技术债，未合并 | 低：不影响功能 |

## 十三、鉴权体系对照（改动后）

| 入口 | 鉴权方式 | 适用场景 | 是否需要「允许远程连接」 |
|------|---------|---------|------------------------|
| Electron 桌面 | 本地密码（IPC `auth-login`） | 本机操作 | 否 |
| 浏览器 `/app` | 本地密码 → Session Cookie | 本机/局域网 Web 访问 | 局域网需要；本机不需要 |
| `/api/v1/*` + Bearer Token | API Token | 远程 client_only 客户端、脚本调用 | 是 |
| `/embed` 员工聊天 | 员工级 Web Token | 嵌入第三方页面 | 仅需 Web 服务 |

**改进意义：** 三种身份（人类密码、Web Session、机器 Token）分层清晰，不再把「给机器用的 Token」强加给「给人类用的 Web 入口」。

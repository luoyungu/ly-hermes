# 我开源了一个 AI 员工管理平台：把 Agent 从"聊天框"变成"可运营团队"

> 本文适合发布到掘金、知乎、V2EX 等技术社区。标题可替换为更吸睛的版本。

---

## 前言

自从 ChatGPT 横空出世，AI 聊天工具层出不穷。但用了一段时间后我发现一个问题：**对话是零散的，Agent 是孤独的**。

每次打开一个新的聊天窗口，上下文就清零了。想让 AI 帮我写日报、巡检代码、回复客服？要么手动复制粘贴，要么写一堆脚本。Agent 能力很强，但缺乏"员工管理"的视角。

所以我做了 **落云.Hermes** —— 一个面向中文团队的 AI 员工管理平台。

---

## 落云.Hermes 是什么？

一句话：**基于 Hermes Agent 生态的桌面工作台，把 AI 从"一段对话"变成"一支可管理的团队"**。

它不是又一个 ChatGPT 客户端。它的核心假设是：

> **每个 AI profile 都应该是一个岗位明确的"员工"，拥有独立的角色、技能、模型、任务和协作渠道。**

你可以把它理解为：
- **AI 员工的 HR 系统** —— 招聘（创建）、配置、考核（Token 用量）、离职（删除）
- **Agent 的运维平台** —— 安装、诊断、更新、远程连接、任务调度
- **办公协作的桥梁** —— 把 AI 产出自动投递到飞书、微信、钉钉

## 技术架构：为什么选 Electron + React？

### 选型逻辑

| 需求 | 选型 | 理由 |
|------|------|------|
| 桌面端体验 | Electron | 需要本地文件系统、SQLite、系统通知、自动更新 |
| 安装引导 | electron-builder | 一键打包 .dmg/.exe/.AppImage |
| Agent 安装 | Node 子进程 | 自动检测 Python、Git、venv，一键装引擎 |
| UI 开发 | React 19 + Tailwind | 组件化、响应式、开发效率高 |
| 数据存储 | better-sqlite3 | 本地嵌入式，零部署，支持备份恢复 |
| 构建工具 | electron-vite + Vite 7 | 热更新快，配置简洁 |

### 架构分层

```
┌──────────────────────────────────────┐
│         Electron 渲染进程             │
│    React + Tailwind + React Router   │
│    - 员工列表 / 对话 / 设置 / 日程    │
└──────────────┬───────────────────────┘
               │ IPC
┌──────────────▼───────────────────────┐
│         Electron 主进程               │
│    - Agent 安装器 (installer.ts)      │
│    - 配置管理 (config.ts)             │
│    - SQLite 数据库操作                │
│    - 自动更新 (electron-updater)      │
└──────────────┬───────────────────────┘
               │ HTTP/WebSocket
┌──────────────▼───────────────────────┐
│      本地 / 远程 Hermes Agent         │
│    - 记忆 / 技能 / 工具 / Gateway     │
└──────────────────────────────────────┘
```

**关键设计决策**：

1. **本机/远程双模式**：Agent 可以跑在本地（开发/个人），也可以跑在服务器（生产/团队），桌面端通过 API Token 连接远程节点。

2. **员工 = Profile + 运营数据**：Hermes 的 profile 只定义了 Agent 的能力，LyHermes 在此基础上叠加了 Token 统计、任务日程、协作渠道等运营层数据。

3. **SQLite 而非远程数据库**：所有数据本地存储，不依赖外部服务，满足隐私和离线需求。

## 核心功能演示

### 1. 一键安装 Agent（降低门槛）

非技术用户最怕什么？配置环境。

LyHermes 的安装器会自动：
- 检测 Python、Git 是否安装
- 创建虚拟环境
- 克隆 Hermes Agent 仓库
- 安装依赖并验证引擎版本

用户只需要点"安装"，等进度条走完。

### 2. 员工管理（从对话到组织）

每个员工都有：
- **基础信息**：名字、头像、角色描述
- **人格设定**：system prompt、语气风格
- **技能配置**：启用哪些工具、安装哪些技能包
- **模型选择**：DeepSeek、OpenAI Compatible、自定义 Base URL
- **协作渠道**：飞书机器人、微信接入、钉钉机器人
- **Web 访问**：独立 Token，可嵌入到任意页面

这不是"聊天记录列表"，这是**组织架构**。

### 3. 定时任务看板（让 AI 主动工作）

以前：每天手动打开聊天框，输入"帮我总结今天的 GitHub 提交"。

现在：在日程看板里配置一个 cron 任务，每天早上 9 点自动执行，结果推送到飞书。

看板显示：
- 任务名称和关联员工
- 下次运行时间
- 上次执行结果（成功/失败）
- 投递状态（是否成功发送到协作平台）

### 4. Token 用量观测（成本可控）

按三个维度聚合：
- **按模型**：哪个模型花最多
- **按员工**：哪个员工最"费钱"
- **按日期**：趋势变化

数据存在本地 SQLite，可随时导出 Excel 做进一步分析。

## 一个实际的部署案例

| 员工 | 角色 | 模型 | 任务 | 投递渠道 |
|------|------|------|------|----------|
| 银月 | 代码审查员 | DeepSeek-Coder | 每次提交后分析 diff | 飞书群 |

三个员工，三个模型，三个任务，三个渠道。**全部在一个桌面应用里管理**。

## 开源与生态定位

LyHermes **不是**要替代官方 Hermes Agent，而是在它之上做了一层"中文桌面产品化"。

| 层级 | 项目 | 定位 |
|------|------|------|
| 引擎层 | Hermes Agent | 自我改进的 Agent 引擎，CLI/Gateway 优先 |
| 客户端层 | 常见 Web 客户端 | 浏览器里聊天，远程访问 |
| **产品层** | **落云.Hermes** | **桌面工作台，安装+员工+日程+渠道+数据** |

如果你对 Agent 的长期运行、多员工管理、办公协作集成有需求，LyHermes 可能是目前中文社区里比较完整的一个选择。

## 写在最后

做这个项目的过程中，最大的感受是：**AI 的瓶颈已经从"模型能力"转移到了"工程化落地"**。
